## 📝 Описание практических заданий (1-6)

### Практическое задание 1 — Верстка страницы магазина
Статическая страница «Магазин курсов по разработке» с карточками курсов.
**Технологии:** HTML, SCSS/CSS, БЭМ

### Практическое задание 2 — CRUD-интерфейс (клиентский)
Страница управления товарами с операциями создания, чтения, обновления и удаления на чистом JavaScript (данные временно хранятся в памяти браузера).
**Технологии:** HTML, JavaScript, SCSS/CSS

### Практическое задание 3 — Работа с DevTools и HTTP
Отчеты (скриншоты) с результатами исследования HTTP-запросов:
- `reports1/` — Запросы к локальному серверу (`GET` списка товаров, товара по ID)
- `reports2/` — Запросы к внешнему API геолокации `ipstack` (IPv4, IPv6)

### Практическое задание 4 — REST API сервер
Express-сервер с CRUD-операциями для сущностей `Product` и `User`, хранение данных в памяти.
Внедрена интерактивная документация через Swagger UI, доступная по роуту `/api-docs`.
**Технологии:** Node.js, Express, nanoid, cors, swagger-jsdoc, swagger-ui-express

### Практическое задание 5 — React-клиент
SPA-приложение на React, подключенное к REST API из задания 4. Реализован список продуктов с возможностью создания, редактирования и удаления через модальные окна.
**Технологии:** React, Vite (опционально), Axios, SCSS

## 🔐 Описание практических заданий (7-11)

### Практическое задание 7 — Базовая аутентификация с bcrypt
Express-сервер с реализованными маршрутами логина (`/api/auth/login`) и регистрации (`/api/auth/register`). Добавлено безопасное хеширование паролей.
**Технологии:** Node.js, Express, bcrypt, nanoid, Swagger

### Практическое задание 8 — JWT токены
Доработка сервера из задания 7: теперь при авторизации выдается Access-токен (JWT), а запросы к `/api/products` и закрытому роуту `/api/auth/me` проверяются промежуточным ПО (Middleware).
**Технологии:** Node.js, Express, bcrypt, jsonwebtoken

### Практические задания 9-10 — React-клиент + Refresh токены + Роутинг
SPA-приложение на React с полноценными страницами и навигацией (`react-router-dom`).
**Бэкенд:** Выдает пару токенов (`access` на 15 минут, `refresh` на 7 дней). Реализован эндпоинт `/api/auth/refresh` для инвалидации старого refresh-токена и выдачи новой пары. Хранилище реализовано в памяти (Set).
**Фронтенд:** Реализованы страницы входа, регистрации и защищенные (Private) роуты. С помощью `axios.interceptors` браузер автоматически отлавливает ошибки `401 Unauthorized`, обновляет токен в фоне через refresh и повторяет запрос незаметно для пользователя. Оба токена безопасно сохраняются в браузере.

### Практическое задание 11 — RBAC (Управление доступом на основе ролей)
Система авторизации разделена по ролям (например, `USER` и `ADMIN`).
- **На бэкенде** установлен `roleMiddleware`: обычные пользователи могут только просматривать товары, администраторы могут добавлять, редактировать и удалять.
- **На фронтенде** кнопки административного управления скрыты для пользователей с базовой ролью.

## 🚀 Как запускать клиент-серверные задания (на примере любой папки начиная с pr7-pr11)

Для тех заданий, которые разделены на `client` и `server`, процедура запуска следующая:

### 1. Установка зависимостей
Откройте два разных терминала.

**Терминал 1 (Бэкенд):**
```bash
cd pr11/server    # перейдите в нужную папку сервера
npm install
```

**Терминал 2 (Фронтенд):**
```bash
cd pr11/client    # перейдите в нужную папку клиента
npm install
```

### 2. Запуск серверов

**Терминал 1 (Бэкенд):**
```bash
node app.js       # Или npm start / nodemon server.js
```
*Бэкенд-сервер будет запущен (обычно на хосте http://localhost:3000).*

**Терминал 2 (Фронтенд):**
```bash
npm start         # Или npm run dev для Vite
```
*Фронтенд будет запущен и автоматически откроется в браузере.*

### 🔍 Проверка документации
После старта бэкенда (например, из заданий 4, 7 или 8), интерактивная Swagger-спецификация доступна по ссылке в браузере:
👉 `http://localhost:3000/api-docs`
